# 销售管理（前端）

财务每天录到账、拆分到车、生成报款文字；每周或每月导银行流水自动对账。后端是 Supabase 项目 `huikuan-system`（伦敦），表、视图、函数和权限都在数据库里，SQL 文件在项目资料 `supabase/` 目录。

## 页面

| 菜单 | 谁能用 | 做什么 |
| --- | --- | --- |
| 工作台 | 所有人（登录后首页） | 到账提交和提成单的审批汇在一起：待办（等我处理）、已办（我处理过、流程还没走完）、已发起（我提交的）、已结束（走完了、我参与过）。点开就是原来的审核、修改页面；单据里有“审批记录”，每一步谁做的、什么时候、退回原因都在 |
| 到账录入 | 管理员、财务 | 录一笔到账（账户、金额、汇率、凭证），拆到一台或多台车，保存后出报款文字。“业务员提交”标签页审核业务员报的到账：通过就生成正式到账，不对就写原因退回；系统里已经录过的可以直接关联 |
| 提交到账 | 业务员 | 客户付了钱，业务员在手机上提交：账户、金额、转账截图、是哪台车的（车不在系统里或客户还没定车，可以手填客户和车型）。财务通过后才算到账；被退回的按原因改好再提交 |
| 支票管理 | 管理员、财务 | 客户给的（分期）支票一张一行：录入（一叠分期支票按号码、按月自动生成，期数跟着排；一张销售订单几台车的，一张支票可以选上几台）、请业务确认、定计划存票日期、存票、钱到账后“生成到账”或对上已录的到账、退票、取消。顶上几个数字是提醒（今天到期、本周到期、到期还没存、已存没到账、已到账没报回款；本周 = 周一到周日，周日那天这个数字就是 0），点开就是清单；每张支票下面有沟通和操作记录。分期支票带合同序号和“第几期 / 共几期”，台账上能按合同序号搜。还能把 Rome 的《支票表》Excel 导进来 |
| 车辆台账 / 我的车辆 | 所有人（业务员只看自己名下） | 合同价、已到账、余额、回款状态；可录期初已到账、优惠折让；导出 Excel |
| 银行对账 | 管理员、财务 | 导入银行流水（CSV/Excel），按“同账户、同金额、日期差 3 天内”自动配对；处理“银行有、没人报”和“录了、银行查不到” |
| 基础资料 | 管理员、财务 | 汇率、客户、业务员、收款账户、款项性质 |
| 提成申请单 | 所有人（业务员只看自己名下；有审批岗位的人还能看提交过的） | 业务员按客户开单（选车、勾客户的付款、填提成金额，可以带附件），提交后在线上逐级审批：销售部 → 应收财务 → 财务负责人 → 公司负责人，批准后财务标记已发放。不用打印签字，打印页只是留底 |
| 用户与权限 | 管理员 | 邀请名单、改角色、停用离职的人；“提成单审批流”里指定每一级由谁审 |

## 中英双语

右上角切换“中文 / EN”。登录前按这台设备上次的选择，没选过就看浏览器语言；登录后按这个人自己上次的选择，同一台电脑几个人用也不互相影响。发到群里的报款文字始终是中文。

- 界面文字直接用中文原文做键：组件里 `const t = useT()`，`t('共 {n} 台', { n })`；组件外用 `tr()`。数据库里的值（状态、款项性质、付款方式）保持中文，只在显示时 `t(值)`。
- 英文对照在 `src/i18n/en.ts`。加了新文字后跑 `npm run i18n:check`，会列出还没有英文的句子和占位不一致的条目。
- 数据库触发器和账号服务发回来的中文报错，由 `trServer()` 按对照表翻译（带金额、编号的按 `{占位}` 匹配）。

## 提成单审批流

业务员提交 → 销售部 → 应收财务 → 财务负责人 → 公司负责人 → 财务发放。每一级在线上点“通过”或“退回”（退回要写原因，改好重新提交后从销售部重新走）。

- 每一级由谁审：管理员在“用户与权限 → 提成单审批流”里选人，存在 `profiles.approval_posts`（审批岗位）。一个岗位可以有几个人，一个人可以兼几个岗位；还没注册的人可以先选上，注册时带过去。
- 岗位和角色分开：角色（管理员、财务、业务员）决定能看到、能录什么；岗位只决定提成单轮到谁审。销售部的审核人可以是业务员账号，他能看到别人提交过的提成单和上面的客户名字，别的还是只看自己的。
- 岗位上还没有人时由管理员代办（工作台待办里会出现）；管理员任何一级都可以代办，审批记录里记的是实际点的人。
- 附件：草稿里随便加减；提交以后只能加（审批的人也可以补），不能去掉。能看到这张提成单的人就能看它的附件。

## 账号

- 新同事：管理员在“用户与权限”把邮箱加进邀请名单，对方在登录页“第一次使用”设密码，马上就能登录。不发确认邮件，名单外的邮箱开不了号。
- 改自己的密码：登录后点右上角“修改密码”（手机上是钥匙图标），先填当前密码，再填两次新密码。
- 忘记密码：管理员在“用户与权限”点“重设密码”，把新密码告诉对方。
- 离职：把“启用”关掉。“删除”只用于注册错、没录过数据的账号。

开号、重设密码、删除账号走 Supabase Edge Function `account`（源码在 `supabase/functions/account/`，部署时关掉 verify_jwt，函数里自己校验管理员身份）。服务端密钥只在 Supabase 服务器上用，不进浏览器。

## 智能填表

到账录入点“新建到账”，最上面有“智能填表”：把业务员在群里发的回款消息、银行的 Credit Alert 贴进去，水单截图传上来（或者 Ctrl+V 粘贴），点“识别并填表”，账户、日期、金额、汇率、付款方和拆分到车都会填好，核对后再保存。只有管理员能用（识别要花 Claude API 的钱），财务账号看不到这张卡片。

- 识别由 Claude 的 API 来做，走 Supabase Edge Function `receipt-ai`（源码在 `supabase/functions/receipt-ai/`，部署时关掉 verify_jwt，函数里自己校验是不是管理员）。它只负责看懂内容，不写数据库；保存还是走原来的 `save_receipt`。
- 开通：在 Supabase 后台 Edge Functions → Secrets 加 `ANTHROPIC_API_KEY`（在 Claude 的开发者后台 platform.claude.com 创建，账户里要有余额）。密钥只放在 Supabase 服务器上，不进浏览器、不进仓库。
- 可选的两个密钥：`CLAUDE_MODEL`（默认 `claude-opus-5-5`，想省钱可以换便宜的型号）、`CLAUDE_EFFORT`（`low` / `medium` / `high`，默认 `medium`）。
- 对不上的地方（账户没认出、大架号系统里没有、客户名有出入、一笔钱付几台车没写每台多少）会列在黄色提示里；没对上车的行先按“大架号未锁定”记到客户名下，点 + 可以直接新增那台车。
- 一次认出好几笔（比如一笔现金、一笔 momo）时，一张表录一笔：保存后再点“新建到账”，剩下的可以接着填，不用再识别一遍。
- 图片在浏览器里先缩到长边 2000、转成 JPEG 再发；一次最多 4 个图片或 PDF（PDF 每个最多 4 MB）。

## 本地运行

```bash
npm install
npm run dev        # 开发
npm run build      # 打包到 dist/，是纯静态文件，放到任何静态网站托管都能用
npm run i18n:check # 检查中英对照有没有漏
```

`.env` 里是 Supabase 地址和 publishable key，这两个本来就是给浏览器用的，公开无妨。**不要**把 service_role key 或数据库密码放进前端。
